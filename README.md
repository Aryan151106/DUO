# React + TypeScript + Vite

This template provides a minimal setup to get React working in Vite with HMR and some Oxlint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the Oxlint configuration

If you are developing a production application, we recommend enabling type-aware lint rules by installing `oxlint-tsgolint` and editing `.oxlintrc.json`:

```json
{
  "$schema": "./node_modules/oxlint/configuration_schema.json",
  "plugins": ["react", "typescript", "oxc"],
  "options": {
    "typeAware": true
  },
  "rules": {
    "react/rules-of-hooks": "error",
    "react/only-export-components": ["warn", { "allowConstantExport": true }]
  }
}
```

See the [Oxlint rules documentation](https://oxc.rs/docs/guide/usage/linter/rules) for the full list of rules and categories.

## Together call rooms

The Focus & Study and Movie Night rooms reuse the native WebRTC signaling in
`src/lib/callSignaling.ts`. Copy `.env.example` to `.env.local` and set
`VITE_TURN_URL`, `VITE_TURN_USERNAME`, and `VITE_TURN_CREDENTIAL` for a TURN
provider. The app includes public fallback relay entries for development, but
production calls should use a private TURN service.

For a self-hosted coturn server, expose UDP/TCP 3478 and TLS 5349, configure a
long-term credential (`lt-cred-mech`), and use a `turns:` URL when possible.
Put the resulting URL and credentials in the local environment used to build
the app; do not commit real credentials. Firebase rules continue to protect the
couple call documents and candidate subcollections.

## Push Notifications & Service Worker Architecture

DUO uses OneSignal Web Push SDK v16 unified under the root PWA Service Worker (`/sw.js`). All push dispatching is executed securely by the authenticated **Node.js server** (`/api/push/send`). No Firebase Cloud Functions are used.

### 1. Required Configuration & Environment Variables

- **Frontend Environment**:
  - `VITE_ONESIGNAL_APP_ID`: The OneSignal App ID shared with the server (e.g., `e0bb43d0-355d-48de-bb9f-0caf33039abb`).
  - **Security Rule**: Never configure REST API keys in client-side environment files, local storage, or frontend code.

- **Node.js Push Server (`duo-socket-server`)**:
  - `ONESIGNAL_REST_API_KEY`: Server-only secret used to authenticate push requests with OneSignal REST API v1. Configure this as an environment secret on Render (or your hosting platform).
  - `ONESIGNAL_APP_ID`: Server OneSignal App ID (must match `VITE_ONESIGNAL_APP_ID`).
  - `ALLOWED_ORIGINS`: Comma-separated list of allowed frontend origins (e.g., `https://av-space-311906.web.app,https://duo-couples-app-8910.web.app`).

### 2. Service Worker Architecture

- **Root Service Worker (`/sw.js`)**: Generated by Vite PWA with Workbox precaching and cache-first navigation.
- **Custom Worker Layer (`/sw-custom.js`)**: Synchronously imported by `/sw.js`, loads OneSignal's worker SDK (`https://cdn.onesignal.com/sdks/web/v16/OneSignalSDK.sw.js`), and manages badge clear and skip-waiting message events.
- **Background Push Display**: There are no competing `push` listeners. OneSignal's SDK handles OS notification display natively when the PWA or browser is closed.

### 3. Phone Testing Procedure

#### Distinction Between Tests
- **Test This Phone (Local)**: Tests local browser notification permissions, vibration engine, and audio playback on the current device. It does **not** send a remote push or test background wakeups.
- **Send Push Test (Server)**: Calls the authenticated `/api/push/send` endpoint on the Node server, which calls OneSignal's REST API targeting the user's `external_id`. This tests remote delivery and waking the phone when closed.

#### Testing On Android
1. Open DUO in Chrome/Edge or install as PWA.
2. In DUO Settings → Alerts & Sounds, tap **Subscribe Phone**. Confirm browser permission is "Granted" and OneSignal status shows "Opted In" with a valid subscription ID.
3. Tap **Send Push Test (Server)** while keeping DUO open to verify initial receipt.
4. Close DUO, swipe it away from recent apps, lock the phone.
5. From partner phone or dev console, send a message or call alert. The phone will display an OS notification with sound and vibration.

#### Testing On iPhone / iPad (iOS 16.4+)
1. Web Push requires iOS 16.4 or later. Standard Safari tabs **cannot** display Web Push notifications.
2. Open DUO in Safari → tap the **Share** button → select **"Add to Home Screen"**.
3. Launch DUO from your Home Screen (standalone PWA mode).
4. In Settings → Alerts & Sounds, tap **Subscribe Phone** and allow notifications when prompted by iOS.
5. Lock the phone or swipe away DUO. Alerts will display on the iOS lock screen and Notification Center.

#### Stale Registration Recovery
If push notifications stop arriving after an app update:
1. In device/browser site settings, clear permissions and stored site data for DUO.
2. Re-open or reinstall the PWA.
3. In DUO Settings, tap **Subscribe Phone** to generate a fresh subscription ID and re-link your Firebase UID.
